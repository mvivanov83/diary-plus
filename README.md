# Дневник+ — электронный дневник частной школы (MVP, этапы 1–2)

Закрытый веб-сервис для частной школы: администратор, учитель и родитель.  
Серверный рендеринг на Express, SQLite, без сборщика и внешних CDN. Интерфейс полностью на русском.

## Что сделано на этапе 1

- **Вход и роли**: администратор, учитель, родитель. Сессии в httpOnly-cookie, хранение сессий в SQLite.
- **Проверка прав на сервере**:
  - учитель видит и редактирует только свои уроки и свой журнал;
  - родитель видит только привязанных к нему детей;
  - администратор — только разделы администратора.
- **Администратор**:
  - сводка школы: ученики, классы, учителя, заявки, незаполненные уроки, средний балл по классам;
  - справочники классов, учеников, учителей, предметов (создание, редактирование, удаление);
  - привязка родителей к ученикам;
  - расписание недели по классу: день, урок №, предмет, учитель, кабинет, время;
  - копирование недели на следующую.
- **Учитель**:
  - «Мой день»: уроки сегодня, таймер до 18:00, красная метка «Незаполнен», напоминание после 17:00;
  - журнал урока: тема, тип (обычный / контрольная / самостоятельная), посещаемость каждого ученика, несколько оценок 2–5, ДЗ с текстом и файлом, комментарий родителям;
  - журнал класса по предмету: сетка «ученики × даты», взвешенный средний балл, итог, процент пропусков;
  - контрольная работа автоматически получает вес 2.
- **Правило 18:00**:
  - урок заполнен, если указаны тема и посещаемость всех учеников;
  - `filled_at` и `fill_status` (`on_time` / `late`) хранятся в SQLite;
  - «Незаполнен» вычисляется после 18:00 Europe/Moscow, если урок так и не заполнен.
- **Родитель**:
  - «Мои дети»: переключатель детей, средний балл, пропуски, токены;
  - дневник на неделю (±5 недель): расписание, темы, оценки, ДЗ с файлами, комментарии учителя, посещаемость.
- **Адаптив**: крупные ячейки журнала под планшет, на 360 px страница не прокручивается по горизонтали — широкая сетка журнала скроллится внутри своего блока.
- **Демо-данные** создаются автоматически при пустой базе.

## Что добавлено на этапе 2

- **Журнал урока**:
  - посещаемость подписана полностью: «Был» (по умолчанию), «Отсутствовал», «Опоздал», «Уважительная»; на узком экране — сокращения Б / Н / О / У с подсказками и легендой;
  - оценки выставляются кнопками 2 / 3 / 4 / 5, несколько нажатий — несколько оценок, крестик удаляет оценку;
  - после сохранения показывается статус «вовремя» или «с опозданием».
- **Журнал класса**: закреплённая шапка, подписи «Средний (взвешенный)», «Итог», «% пропусков», переключатель «Неделя / Месяц / Четверть»; средние пересчитываются за выбранный период, у среднего есть подсказка о формуле.
- **Администратор**:
  - экран «Заявки родителей»: одобрить с привязкой к ученику или отклонить;
  - отчёт «Заполнение журнала» за месяц по учителям и экспорт CSV (BOM UTF-8, `;` для Excel);
  - на дашборде видны число заявок и незаполненных уроков.
- **Самостоятельная регистрация родителя** `/register`: ФИО, e-mail, пароль, ФИО и класс ребёнка. Аккаунт получает статус «на модерации», письмо-подтверждение пишется в лог сервера, до одобрения открывается экран «Заявка на рассмотрении».
- **Учитель**: список учеников и карточка ученика — оценки по предметам, средние, пропуски, токены, внутренние заметки (родителю не видны); начисление и списание токенов с причиной.
- **Родитель**: «Успеваемость» (средние по предметам, SVG-график динамики по неделям без CDN, посещаемость), «Токены» (баланс и история), «Уведомления» (оценки, ДЗ, расписание, токены, комментарии; счётчик непрочитанных).
- **Навигация** исправлена и проверена у всех трёх ролей, включая «Мои дети» с любых страниц родителя.

## Стек

- Node.js **22.x** (`engines` и `.nvmrc`)
- Express 4
- SQLite через **better-sqlite3 12.x** (не 13.x — на Railway 13.x падает с Segmentation fault)
- `bcryptjs` для паролей
- `multer` для файлов домашних заданий
- HTML/CSS/JS без сборщика, шрифт Inter с системным fallback

## Как запустить самому

Нужен Node.js 22.x. Проверить версию:

```bash
node -v
```

Установка и запуск из папки проекта:

```bash
npm install
npm start
```

Приложение: <http://localhost:3000>

Порт по умолчанию — `3000`. Если он занят, задайте другой:

```powershell
$env:PORT=3200
npm start
```

или в одной строке PowerShell:

```powershell
$env:PORT=3200; npm start
```

Остановить сервер — `Ctrl+C` в терминале. Фоновый процесс, который мог быть запущен при проверке, не обязателен: приложение полностью поднимается командой `npm start`.

При первом запуске автоматически создаются:

- `./data/app.db` — база;
- `./data/uploads` — файлы ДЗ;
- демо-школа из ТЗ.

Сбросить демо-данные: остановить сервер, удалить `data/app.db` и `data/uploads`, запустить снова.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера |
| `DATABASE_FILE` | `./data/app.db` | Путь к файлу SQLite; папки создаются автоматически |
| `UPLOADS_DIR` | `./data/uploads` | Папка для файлов ДЗ; создаётся автоматически |
| `SESSION_SECRET` | локальный fallback | Секрет для HMAC-хеширования токенов сессий |
| `NODE_ENV` | — | В `production` статика кешируется на час |

## Правило 18:00

1. Учитель сохраняет урок с темой и посещаемостью всех учеников.
2. Время первого заполнения пишется в `lessons.filled_at` (UTC ISO).
3. Если `filled_at` ≤ 18:00 Europe/Moscow дня урока — `fill_status = on_time` («Вовремя»).
4. Если позже — `fill_status = late` («С опозданием»).
5. Если до 18:00 урок не заполнен — «Ожидает»; после 18:00 — «Незаполнен» (красный).
6. Повторное редактирование не меняет время первого заполнения и статус.

Москва — фиксированный UTC+3, дедлайн хранится как 15:00 UTC соответствующего дня.

## Развёртывание на Railway

1. Загрузите репозиторий на GitHub и создайте проект Railway из репозитория.
2. Railway прочитает `.nvmrc` / `engines` и использует Node.js 22.
3. Build command: `npm install`; start command: `npm start` (или `npm start` из `package.json`).
4. Задайте переменные:
   - `SESSION_SECRET` — длинная случайная строка;
   - `DATABASE_FILE=/data/app.db`;
   - `UPLOADS_DIR=/data/uploads`.
5. **Обязательно подключите Volume** и смонтируйте его в `/data`. Без volume SQLite-база и файлы ДЗ не сохранятся после Redeploy.
6. `PORT` Railway задаёт сам — приложение читает его из окружения.

Проверка здоровья: `GET /healthz` → `{"ok":true,...}`.

## Безопасность и доступ

- Пароли — bcrypt, сессии — случайный токен в httpOnly-cookie `diary_sid`, в БД хранится HMAC-хеш.
- `SameSite=Lax`, `Secure` автоматически при HTTPS (Railway за прокси).
- Все SQL-запросы параметризованы.
- Весь пользовательский текст в HTML проходит через одну функцию `escapeHtml()`.
- Файлы ДЗ отдаются только администратору, владельцу-учителю или родителю ученика этого класса.
- Проверка владения уроком/ребёнком выполняется на сервере, а не только скрытием ссылок.
